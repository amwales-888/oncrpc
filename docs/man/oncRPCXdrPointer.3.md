# oncRPCXdrPointer(3)

## NAME

oncRPCXdrPointer - XDR routine for optional data

## SYNOPSIS

```c
#include <xdr.h>

int oncRPCXdrPointer(oncRPCXdr *xdrs, void **pp, size_t size, oncRPCXdrProc proc);
```

## DESCRIPTION

`oncRPCXdrPointer()` handles XDR optional data, `type *name`: a boolean
saying whether a value follows, then the value encoded by `proc`. In C the
value lives behind the pointer `*pp`, which is `NULL` when there is none.

- **Encode:** sends `FALSE` if `*pp` is `NULL`, otherwise `TRUE` and the
  value.
- **Decode:** sets `*pp` to `NULL`, or allocates a zeroed object of `size`
  bytes from the stream's allocator and decodes the value into it.
- **Free:** frees what the value owns with `proc`, releases the object and
  sets `*pp` to `NULL`.

Optional data is how XDR expresses linked lists: a structure whose last
field is an optional pointer to the next one.

## RETURN VALUE

Non-zero on success; 0 if the flag is not a valid boolean, the allocator
fails, `proc` fails, or the stream has already failed.

## EXAMPLE

A linked list (`struct entry { string name<>; entry *next; };` in `.x`):

```c
#include <xdr.h>

struct entry {
    char         *name;
    struct entry *next;
};

int xdr_entry(oncRPCXdr *xdrs, void *obj)
{
    struct entry *e = obj;
    return oncRPCXdrString(xdrs, &e->name, ONCRPC_XDR_UNBOUNDED) &&
           oncRPCXdrPointer(xdrs, (void **)&e->next, sizeof(struct entry), xdr_entry);
}
```

Each node is one more level of recursion, so a very long list uses a lot
of stack. Code generated by oncrpcgen for such a list works the same way.
