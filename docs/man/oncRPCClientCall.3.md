# oncRPCClientCall(3)

## NAME

oncRPCClientCall - start a remote procedure call

## SYNOPSIS

```c
#include <oncrpc.h>

typedef void (*oncRPCCallCb)(oncRPCClient *clnt, oncRPCStat status, void *res, void *data);

oncRPCStat oncRPCClientCall(oncRPCClient *clnt, uint32_t proc,
                            oncRPCXdrProc xargs, const void *args,
                            oncRPCXdrProc xres, void *res,
                            oncRPCCallCb cb, void *data);
```

## DESCRIPTION

`oncRPCClientCall()` starts a call of procedure `proc` of the client's
program and version, and returns at once. When the call has finished,
successfully or not, `cb` runs with its status.

- **Arguments.** `args` is encoded with the XDR routine `xargs` before the
  function returns, so it may be a local variable that goes out of scope
  straight after. `xargs` may be `NULL` when the procedure takes no
  arguments.
- **Results.** When the reply arrives, the results are decoded into `res`
  with `xres`. `res` must therefore stay valid until `cb` runs (a static
  or heap object, not a local variable of the calling function), and
  should be zero-initialised. `xres` may be `NULL` when the procedure
  returns nothing.
- **Callback.** `cb(clnt, status, res, data)` runs once, from the event
  loop, never inside `oncRPCClientCall()`. `res` is the pointer given
  here. On `ONCRPC_OK` it holds the results, and anything the decode
  allocated (strings, arrays) must eventually be released with
  `oncRPCXdrFree(oncRPCClientAllocator(clnt), xres, res)`. On failure
  nothing needs releasing. `cb` may be `NULL` if the outcome does not
  matter.

Any number of calls may be outstanding on one client; their replies are
matched by transaction id, in whatever order they arrive. Over UDP a call
is resent at the retry interval ([oncRPCClientSetRetry(3)](oncRPCClientSetRetry.3.md))
until a reply arrives. Every call fails with `ONCRPC_ERR_TIMEDOUT` if it
has not finished within the client's timeout
([oncRPCClientSetTimeout(3)](oncRPCClientSetTimeout.3.md)), counted from
this function.

Code generated by `oncrpcgen` wraps this function in one typed stub per
procedure, such as `oncRPCAddV1(client, &a, &b, &sum, cb, data)`; see
[oncrpcgen(1)](oncrpcgen.1.md).

After `cb` has run with an error, more detail is available from
[oncRPCClientLastError(3)](oncRPCClientLastError.3.md).

## RETURN VALUE

`ONCRPC_OK` if the call was started: `cb` will run exactly once.
Otherwise the call was not started and `cb` will not run:

- `ONCRPC_ERR_INVALID`: `clnt` is `NULL` or closing.
- `ONCRPC_ERR_CANTENCODE`: `xargs` failed, or a custom credential could
  not be made.
- `ONCRPC_ERR_CANTSEND`: over UDP, the call is larger than a datagram.
- `ONCRPC_ERR_NOMEM`: the allocator failed.
- the status the client failed with, if it failed for good (for example
  `ONCRPC_ERR_UNKNOWNHOST`).

The status given to `cb` is one of the `oncRPCStat` values, for example
`ONCRPC_ERR_TIMEDOUT`, `ONCRPC_ERR_PROCUNAVAIL`, `ONCRPC_ERR_AUTHERROR`,
`ONCRPC_ERR_CANTRECV` or `ONCRPC_ERR_CANCELLED`.

## EXAMPLE

Three calls outstanding at once, each with its own result:

```c
#include <stdio.h>
#include <oncrpc.h>

#define SQUARE 2u

static int xdr_int(oncRPCXdr *xdrs, void *obj)
{
    return oncRPCXdrInt32(xdrs, (int32_t *)obj);
}

static int32_t results[3];   /* one per call, alive until the callbacks */

static void on_square(oncRPCClient *client, oncRPCStat status, void *res, void *data)
{
    (void)client;
    if (status == ONCRPC_OK)
        printf("%d squared is %d\n", *(int *)data, (int)*(int32_t *)res);
    else
        printf("%d: %s\n", *(int *)data, oncRPCStrError(status));
}

void square_three(oncRPCClient *client)
{
    static int inputs[3] = { 3, 4, 5 };
    int i;

    for (i = 0; i < 3; i++) {
        int32_t arg = inputs[i];   /* encoded at once: a local is fine */
        if (oncRPCClientCall(client, SQUARE, xdr_int, &arg, xdr_int, &results[i],
                             on_square, &inputs[i]) != ONCRPC_OK)
            printf("could not start call %d\n", i);
    }
}
```
